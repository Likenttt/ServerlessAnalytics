# 凌云志 · 佳明手表武侠养成

一介凡夫，志在凌云。每天走路、爬楼、运动就是练功，再加上手表上的出拳、腾跃、站桩、吐纳四门功课，从「凡夫俗子」一路修炼到能凌空飞行的「御风宗师」。

## 能实现吗

能。需要的能力 Connect IQ 都有：

| 需求 | Connect IQ 能力 |
| --- | --- |
| 读全天步数、爬楼、强度分钟 | `ActivityMonitor.getInfo()`；没打开游戏的日子用 `getHistory()`（约 7 天）补算 |
| 识别出拳、跳跃、静立 | `Sensor.registerSensorDataListener`，25 Hz 加速度计 |
| 吐纳时读心率 | `Sensor.enableSensorEvents` |
| 存档 | `Application.Storage` |
| 节奏提示 | `Attention.vibrate` |
| 在 Glance 里看境界 | `getGlanceView()` |
| 角色与动画 | `Dc` 图元绘制 + `Timer`，自动适配各种屏幕 |

需要取舍的地方：

- 应用不在前台时不运行，所以修为不是实时涨，而是每次打开时结算。关着的日子用手表历史补算，超过约 7 天没打开的那几天会丢。
- 睡眠、Body Battery 对应用开放有限，所以「心境」改由日课和吐纳驱动。
- 动作识别是阈值算法，需要在真表上微调（见[调参](#调参)）。

关于 Beasties：我没查到佳明官方名为 Beasties 的应用的公开资料，这里参考的是同类「运动养宠物」的玩法：从零开始 → 随真实运动成长 → 按运动方式分化形态 → 每天照料、冷落会萎靡。放到武侠里，就是境界、门派和「萎靡不振 / 神采奕奕」。

## 玩法

### 四项根骨

| 属性 | 来自日常运动 | 来自手表修炼（每项每天最多 60 点） |
| --- | --- | --- |
| 体魄 | 每 100 步 +1 | 出拳：30 秒，每 2 拳 +1 |
| 轻功 | 每爬 1 层 +5（没有气压计的表：每 200 步 +1） | 腾跃：30 秒，每 2 跳 +1 |
| 内力 | 中等强度每分钟 +2，高强度每分钟 +4 | 站桩：60 秒，每静立 3 秒 +1 |
| 心境 | 每天第一次打开 +5；每完成一项日课 +10，三项全完成再 +10 | 吐纳：6 息，每息 +3，心率下降再 +2 |

四项之和就是修为。

### 九重境界

| 境界 | 所需修为 | 突破试炼 | 额外条件 | 形象 |
| --- | --- | --- | --- | --- |
| 凡夫俗子 | 0 | — | — | 布衣 |
| 初窥门径 | 150 | 站桩，静立 20 秒 | | 抱拳 |
| 登堂入室 | 600 | 出拳，30 秒 20 次 | | |
| 三流好手 | 1,500 | 吐纳 3 息 | | 拜入门派，换道袍 |
| 二流高手 | 3,500 | 腾跃，30 秒 20 次 | | 真气环绕 |
| 一流高手 | 7,000 | 站桩，静立 60 秒 | | 踏空悬浮（踏雪无痕） |
| 绝顶高手 | 12,000 | 出拳，30 秒 50 次 | 曾单日走满 12,000 步 | 衣袂飘飞 |
| 一代宗师 | 20,000 | 腾跃，30 秒 40 次 | 曾单日爬满 15 层（无气压计：单日强度 45 分钟） | 凌空虚渡 |
| 御风宗师 | 32,000 | 吐纳 6 息 | 连续 7 天完成日课 | 乘云御风 |

每项属性都不能低于下一境界所需修为的 12%，偏科会卡住突破，「根骨」页会提示最弱的一项该怎么练。

### 门派

突破到三流好手时，由当时最强的属性决定门派和道袍颜色：体魄 → 少林（橙黄），轻功 → 逍遥（天蓝），内力 → 武当（白），心境 → 峨眉（紫）。

### 日课与状态

每天三项日课，目标随境界提高：

- 步行 5000 + 500 × 境界
- 爬楼 3 + 境界 / 2 层（没有气压计的表改为当天腾跃 20 + 5 × 境界 次）
- 强度分钟 10 + 3 × 境界

角色的姿态跟着当天的状态变：几乎没动是「萎靡不振」（垂头打盹），平常是「气定神闲」（抱拳），日课全部完成是「神采奕奕」（马步推掌）。

### 节奏

按上面的规则模拟几类玩家（每周有一天运动量比平时大）：

| 玩家 | 三流 | 一流 | 绝顶 | 宗师 | 御风 |
| --- | --- | --- | --- | --- | --- |
| 轻度：6000 步、4 层、10 强度分钟 | 第 11 天 | 第 51 天 | 需先走一次 1.2 万步 | | |
| 普通：8000 步、8 层、25 强度分钟 | 第 6 天 | 第 27 天 | 第 46 天 | 第 77 天 | 需连续 7 天达成宗师日课 |
| 活跃：1 万步、12 层、45 强度分钟 | 第 5 天 | 第 19 天 | 第 32 天 | 第 53 天 | 第 85 天 |
| 运动员：1.4 万步、20 层、80 强度分钟 | 第 3 天 | 第 14 天 | 第 23 天 | 第 39 天 | 第 61 天 |

第一次突破当天就能完成；后三重境界需要现实里真的练出来（单日 1.2 万步、单日 15 层、连续 7 天日课），光靠挂机上不去。

## 操作

- **主界面**：上 / 下键（或上下滑动）翻页：角色 → 根骨 → 日课 → 江湖录
- **确认键（或点按）**：打开修炼菜单：突破、出拳、腾跃、站桩、吐纳、心法
- **修炼**：按键开始 → 3 秒倒计时 → 练功 → 结算，按键回到角色；中途按返回键放弃，不计分
- **Glance**：显示门派境界、突破进度、当天日课完成数

## 构建与运行

需要 Connect IQ SDK（建议 7.x 或更新）和 VS Code 的 Monkey C 扩展。

```sh
# 命令行构建（以 fr965 为例）
monkeyc -f monkey.jungle -d fr965 -o bin/lingyun.prg -y /path/to/developer_key.der
connectiq &
monkeydo bin/lingyun.prg fr965
```

在模拟器里测试：

- 模拟器的 `Simulation` 菜单里可以设置 Activity Monitor 数据（步数、楼层、强度分钟），回到主界面即结算。
- 调试版菜单末尾有 `DEBUG` 项：四项各 +500，并填好单日纪录和连续日课，方便直接试突破。
- 调试版在练功中按确认键可以模拟一次动作（模拟器通常没有加速度数据）。发布版没有这两个功能。

真机：`Monkey C: Build for Device` 生成 `.prg`，拷到手表的 `GARMIN/APPS` 目录。

## 调参

- 所有数值在 `source/Rules.mc`：境界所需修为、试炼目标、额外条件、每日上限、日课奖励。
- 动作识别阈值在 `source/TrainView.mc` 的 `begin()`：出拳 2200 / 1400 mg、间隔 6 个采样；腾跃 2000 / 1300 mg、间隔 8 个采样；站桩每秒波动超过 160 mg 记为「晃」。建议先在真表上打印加速度幅值再定。

## 验证情况

- 开发环境无法访问 developer.garmin.com，拿不到 SDK，所以**还没有用 monkeyc 编译过，也没有在模拟器或真表上运行过**。
- 已经做的检查：
  - 用 prettier-plugin-monkeyc 解析并格式化全部源码。
  - 用一个自写的 Monkey C 解释器和 Toybox API 桩做静态检查：未定义符号、参数个数、glance 作用域、`(:debug)` / `(:release)` 成对。
  - 跑了 64 项场景断言：重复结算不多算、跨天与多天补算、两种历史时间戳约定、训练每日上限、试炼成败、三流定门派、无气压计的表、发布版无调试项、glance。预览图也来自这个解释器。
- 第一次编译如果报类型错误，多半是类型注解问题，按编译器提示调整即可。
